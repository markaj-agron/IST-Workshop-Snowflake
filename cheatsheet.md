## Why Snowflake?

### Real-world scenario: SwissBike SA

SwissBike SA is a Swiss SME selling bicycles and accessories online. As the company grows, data is generated by multiple systems:

- E-commerce platform
- ERP system
- CRM system
- Marketing tools

Management needs reliable answers to questions such as:

- Which countries generate the most revenue?
- Who are our most valuable customers?
- Which products should we promote?
- How are sales evolving over time?

Without a centralized solution, data is scattered across multiple systems and reports become slow, inconsistent and difficult to maintain.

 ### What does Snowflake do?

Snowflake is a cloud-native data warehouse that centralizes data from multiple sources and enables large-scale analytical processing.

#### Inputs

- CSV files
- Databases
- ERP systems
- CRM systems
- APIs
- Streaming data

#### Outputs

- SQL query results
- Dashboards (Power BI, Tableau, Looker)
- Reports
- Data for machine learning and analytics

## Benefits and limitations

### Benefits

#### Separation of Storage and Compute

Storage and computing resources are managed independently.

Benefits:

- Flexible scaling
- Better cost control
- No infrastructure management

### Massively Parallel Processing (MPP)

Snowflake distributes query execution across multiple computing resources.

Benefits:

- Fast analytical queries
- Efficient processing of large datasets
- Good support for concurrent users

### Time Travel

Recover data that was accidentally modified or deleted.

Example:

```sql
UNDROP TABLE SALES;
```

### Zero-Copy Cloning

Instantly create testing environments without physically copying data.

Example:
    
```sql
CREATE DATABASE TEST_DB
CLONE PROD_DB;
```

### Fully Managed Service

No server installation or maintenance required.

### Limitations

#### Vendor lock-in

Applications and processes become dependent on Snowflake's ecosystem.

#### Cost management

Poorly optimized queries or oversized warehouses can generate unnecessary costs.

#### Cloud dependency

Requires internet access and depends on the availability of cloud providers.

#### Not designed for OLTP

Snowflake is optimized for analytics (OLAP), not transactional applications.

## Cost structure

Snowflake pricing is mainly based on:

### 1. Storage

Measured in:

- Terabytes (TB) stored per month

Example:

```text
500 GB ≈ 0.5 TB
Cost: ~20 CHF/month
```
### 2. Compute

Measured in:

- Credits consumed by Virtual Warehouses

Factors:

- Warehouse size
- Execution time
- Number of clusters

## Common commands / operations / usage patterns

### Query sample data

```sql
SELECT *
FROM SNOWFLAKE_SAMPLE_DATA.TPCH_SF1.ORDERS
LIMIT 100;
```

### Count records

```sql
SELECT COUNT(*)
FROM CUSTOMER;
```

### Revenue by country

```sql
SELECT
    N.N_NAME,
    SUM(L.L_EXTENDEDPRICE) AS REVENUE
FROM LINEITEM L
JOIN ORDERS O
    ON L.L_ORDERKEY = O.O_ORDERKEY
JOIN CUSTOMER C
    ON O.O_CUSTKEY = C.C_CUSTKEY
JOIN NATION N
    ON C.C_NATIONKEY = N.N_NATIONKEY
GROUP BY N.N_NAME;
```

### Resize a warehouse
```sql
ALTER WAREHOUSE COMPUTE_WH
SET WAREHOUSE_SIZE='SMALL';
```

### Suspend a warehouse
```sql
ALTER WAREHOUSE COMPUTE_WH
SUSPEND;
```

### Resume a warehouse
```sql
ALTER WAREHOUSE COMPUTE_WH
RESUME;
```

### Time Travel
```sql
DROP TABLE CUSTOMER_PROD;

UNDROP TABLE CUSTOMER_PROD;
```

### Zero-Copy Clone
```sql
CREATE TABLE CUSTOMER_TEST
CLONE CUSTOMER_PROD;
```

### Query Profile (MPP)

After executing a query:

```text
Monitoring
→ Query History
→ Query Profile
```

The Query Profile displays:

- Table Scan
- Join
- Aggregate
- Sort

and helps understand how Snowflake executes analytical workloads using MPP.

### When should a SME use Snowflake?

#### Recommended

- Business Intelligence
- Data Warehousing
- Analytics
- Reporting
- Data Science
- Multi-source data integration

#### Not recommended

- Small applications with limited data
- OLTP workloads
- Projects requiring full infrastructure control

Recommendation: Snowflake is an excellent choice for SMEs that need scalable analytics with minimal operational overhead, but organizations must actively monitor costs and evaluate vendor lock-in risks.
